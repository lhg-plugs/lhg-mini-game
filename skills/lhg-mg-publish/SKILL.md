# lhg-mg-publish：测试与发布

> 目标：游戏上线前最后一道门——功能、性能、兼容三轮验完再发，
> 发出去的游戏在 3 年前的千元机上也能玩。
> 本 skill 的"三轮测试清单"与"发布门禁"为本插件原创。

## 1. 何时使用

- 游戏代码写完、准备发给用户/上线时 → 加载本 skill
- `/mini-game-audit` 报 blocker 时 → 按第 3 节定位修复
- 用户问"游戏做好了怎么发出去"时 → 按第 4 节给托管方案

## 2. 输入与输出

- **输入**：单个 `.html` 游戏文件（lhg-mg-dev 产出）
- **输出**：审计报告（blocker 清零）+ 发布交付物（文件 + 访问方式 + 测试结论）
- **门禁**：blocker 不清零不许发布（硬门在 git commit 前也会拦）

## 3. 三轮测试清单

### 第一轮：功能测试（自己玩 3 遍）

- [ ] 开始按钮 → 游戏正常启动，计时/计分开始走
- [ ] 核心操作 3 次 → 每次都有反馈（音效/动画/分数变化）
- [ ] 触发结束条件 → 结束屏出现，分数/最高分正确
- [ ] "再来一局" → 状态完全重置（分数清零、对象池清空）
- [ ] 分享按钮 → 海报正常生成（含分数+二维码位）
- [ ] 静音开关 → 开/关都有效，刷新后保持上次选择（可选）

### 第二轮：确定性审计（脚本说了算）

```bash
python3 scripts/audit/gameplay_audit.py --target <游戏文件或目录> --format text
```

- blocker 必须清零（缺结束条件/计分/触摸/viewport/单文件违规）
- warning 修掉或写豁免理由（如"纯展示页无触摸需求"）
- nit 记入"已知问题"清单，不阻塞发布
- 修复后重跑，直到 `blocker 0`

### 第三轮：真机兼容（借 2 台手机）

- [ ] 安卓微信内置浏览器：触摸跟手、无滚动穿透
- [ ] iPhone Safari：音频正常（需用户手势后初始化）、无缩放
- [ ] 低端机：连续玩 3 分钟，主观无卡顿
- [ ] 横竖屏切换：布局不错乱（或已提示建议方向）

**诚实声明**：没有条件做第三轮时，明确告诉用户"未做真机测试，微信内置浏览器
行为以实测为准"，不许说"应该没问题"。

## 4. 托管与分发

单文件游戏的托管极简，按推荐度排序：

1. **静态托管**（Cloudflare Pages / Vercel / GitHub Pages / 对象存储）：上传单个
   html 即得 https 链接，免费、免运维。**微信内分享必须 https**。
2. **二维码**：链接转二维码印在海报/传单上，线下场景扫码即玩。
3. **公众号/小程序跳转**：公众号菜单、文章内链直接放 https 链接。
4. **不建议**：塞进 App 内嵌 WebView（需客户端发版配合，小白搞不定）。

分发检查：
- [ ] https 可访问（http 在微信内会被拦截）
- [ ] 文件 < 300KB（MG-HYG-001），首屏 3 秒内可玩
- [ ] 分享出去的标题/缩略图正常（微信抓取 `<title>` 与第一张图）

### 4.4 微信生态特殊要求

- **域名报备**：链接首次在微信内打开可能提示"非微信官方网页"，属正常；被用户举报
  诱导分享才会封域名（合规见 lhg-mg-viral 第 6 节）。
- **分享卡片**：微信抓取 `<title>` 做标题、抓第一张可见图做缩略图；想好看就
  在页面顶部放一张 300×300 的品牌图（CSS 隐藏也行，display:none 的不被抓）。
- **下拉小程序**：H5 游戏不能直接转微信小游戏（那是另一套 runtime），不要混淆概念；
  用户问"能上微信小游戏吗"，答案是：需要按微信小游戏规范重写，不是一键转换。

## 5. 数据埋点（可选，不做不扣分）

想知道游戏有没有人玩，加三行埋点即可（localStorage 版，零后端）：

- 日活：每天首次打开记一条 `mg_dau_日期`
- 局数：每次"开始游戏"计数
- 分享率：分享点击 / 结束屏展示

有后端时再上正式统计（不要为埋点引入整套 SDK，得不偿失）。

## 6. 发布交付报告（固定格式）

```markdown
# 《游戏名》发布报告
- 文件：game.html（xx KB，单文件）
- 访问：https://xxx（二维码附后）
- 审计：blocker 0 / warning 0 / nit 1（DPR说明…）
- 测试：功能 3 遍通过；真机：安卓微信✓ / iPhone Safari✓
- 裂变点：战绩海报（炫耀）+ 本地最高分（竞争）
- 已知问题：低端机粒子全开时轻微掉帧（已设上限，可接受）
- 需人工：把链接配到公众号菜单（AI 做不了）
```

### 4.5 线上问题排查速查

| 现象 | 先查 | 常见原因 |
|---|---|---|
| 微信内打不开 | 链接协议 | http 被拦截，必须 https |
| 打开白屏 | 文件大小/控制台 | 单文件 > 1MB 加载慢；JS 报错（微信开发者工具远程调试看） |
| 点按没反应 | 触摸事件 | 只绑了 click；或被 UI 覆盖层挡住（pointer-events） |
| 声音不出 | 音频初始化 | AudioContext 在用户手势前创建被浏览器静默 |
| 海报分享黑图 | Canvas 污染 | 跨域图片画进 Canvas 导致 toDataURL 抛异常（用矢量绘制避开） |
| 分数不保存 | 存储 | 微信隐身/无痕模式 localStorage 抛异常，try/catch 是否包了 |

### 4.6 迭代节奏

- v1.0 上线 → 收集 3 天数据（见 lhg-mg-viral 4.6 指标）
- 先调数值（难度/时长/奖励），再加玩法；一次只动一个变量
- 每次更新保留旧文件（如 game-v1.html），出问题 1 分钟回滚

## 7. 反模式

- ❌ 跳过审计直接发：blocker 上线 = 用户手机上玩不了
- ❌ 只在电脑 Chrome 测完就发：微信内置浏览器是另一个世界
- ❌ http 链接发出去：微信内直接拦截，前功尽弃
- ❌ 大文件硬发：2MB 的单文件，4G 下 10 秒白屏
- ❌ "应该没问题"式交付：没测就说没测，诚实比完美重要

## 8. 自检与反馈

**质检门**：
- [ ] 审计 blocker 清零（附报告截图或文本）
- [ ] 三轮测试清单逐项打勾（未做项明确标注）
- [ ] https 链接可访问，文件 < 300KB
- [ ] 交付报告已给用户，含"需人工"事项

**标准冒烟用例**：对 fixtures/mg-good/game.html 跑发布流程 →
审计零 blocker，交付报告可生成。

**一键反馈**：发现新的机型坑或托管坑，以 `[QC] <一句话>` 为标题提交到
https://github.com/lhg-plugs/lhg-mini-game/issues，正文写清"复现步骤 → 实际表现 →
期望表现"。
