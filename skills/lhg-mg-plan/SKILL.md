# lhg-mg-plan：玩法规划与模板匹配

> 目标：把用户一句话的"想做个小游戏"变成可执行的玩法设计——模板先行、机制参数化，
> 结束条件和计分规则在写第一行代码前就定死。
> 本 skill 的方法论为原创总结（玩法模板库与参数化框架均为本插件原创）。

## 1. 何时使用

- 用户说"做个小游戏/H5游戏/营销游戏"时 → 先加载本 skill 做玩法规划
- 用户已有玩法想法但说不清规则时 → 用第 4 节澄清
- 写代码前 → 输出第 5 节的一页纸设计文档，确认后再开工
- 审计报 MG-DESIGN-001/002（缺结束条件/计分）时 → 回到本 skill 补设计

## 2. 输入与输出

- **输入**：用户一句话玩法描述（+ 可选：目标人群、投放场景、期望时长）
- **输出**：玩法模板匹配结果 + 一页纸游戏设计文档（GDD）
- **不输出**：代码（那是 lhg-mg-dev 的事）

## 3. 玩法模板库（四类，机制参数化）

先匹配模板，再填参数。不要从零发明玩法——四类模板覆盖 90% 营销/获客小游戏。

### 模板 A：合成类（代表：2048、合成大西瓜）

| 参数 | 说明 | 典型取值 |
|---|---|---|
| 元素种类 | 可合成的物品 | 5~8 种，层层递进 |
| 合成规则 | 两个相同 → 高一级 | 相同碰撞即合成 |
| 失败条件 | 堆满 / 超出顶线 | 顶线停留 3 秒判负 |
| 计分 | 合成得分 = 等级²×10 | 连击加成 |
| 难度曲线 | 掉落速度/新元素出现率随时间提升 | 每 30 秒一档 |
| 时长 | 单局 1~3 分钟 | 适合碎片时间 |

### 模板 B：跳跃/躲避类（代表：跳一跳、飞机大战）

| 参数 | 说明 | 典型取值 |
|---|---|---|
| 核心操作 | 点按/滑动/长按 | 单一操作，3 秒学会 |
| 失败条件 | 掉落 / 碰撞 / 超时 | 一次失误即结束（短局多玩） |
| 计分 | 距离/存活时间/收集物 | 每 10 秒难度+1 档 |
| 难度曲线 | 速度/障碍密度递增 | 指数增长，前 30 秒友好 |
| 时长 | 单局 30 秒~2 分钟 | 失败成本低，驱动"再来一局" |

### 模板 C：答题类（代表：知识竞答、品牌问答）

| 参数 | 说明 | 典型取值 |
|---|---|---|
| 题量 | 单局题目数 | 5~10 题，答完即一局 |
| 计时 | 单题限时 | 10~15 秒/题，超时判错 |
| 计分 | 答对得分 + 连对加成 | 连对 3 题起加成 |
| 结束条件 | 题库答完 / 错 3 题出局 | 二选一，提前声明 |
| 难度曲线 | 由易到难排列 | 前 3 题送分建立信心 |
| 时长 | 单局 1~2 分钟 | 适合品牌知识植入 |

### 模板 D：抽奖类（代表：大转盘、刮刮卡）

| 参数 | 说明 | 典型取值 |
|---|---|---|
| 参与门槛 | 免费 / 完成小任务后抽 | 建议先玩后抽（防羊毛党） |
| 奖品池 | 奖品 + 中奖率 | 公示概率，合规要求 |
| 次数限制 | 每人每天 N 次 | 分享可额外获得次数（裂变钩子） |
| 防刷 | 同设备/同 IP 限次 | 前端限次 + 后端校验（真奖品必须有后端） |
| 时长 | 单次 10~30 秒 | 纯刺激，即开即走 |

### 匹配规则

1. 用户描述含"合成/合并/消除" → 模板 A
2. 含"跳/躲/飞/跑/接" → 模板 B
3. 含"答题/问答/测试/挑战知识" → 模板 C
4. 含"抽奖/转盘/刮奖/红包" → 模板 D
5. 都不含 → 按"目标"选：获客留资选 D，品牌曝光选 C，病毒传播选 B，深度停留选 A
6. **匹配后必须告诉用户选了哪个模板、为什么**，用户可换

## 4. 需求澄清（≤5 个问题，先开放后收敛）

1. 这个游戏做给谁玩？（目标人群：如宝妈、大学生、品牌粉丝）
2. 玩家玩完之后你希望他做什么？（加微信/分享/留资/下单——决定裂变点设计）
3. 单局期望多长？（30 秒爽局 / 2 分钟沉浸——决定模板参数）
4. 有没有必须出现的品牌元素？（Logo、产品、口号——决定美术植入点）
5. 真奖品还是纯好玩？（有真奖品 → 必须后端 + 防刷声明，见第 6 节反模式）

问完即止，不要追问第六个。信息够了就出设计文档。

## 5. 一页纸游戏设计文档（GDD）

每个游戏开工前必须输出，格式固定：

```markdown
# 《游戏名》设计文档 v1.0
- 模板：B（跳跃/躲避类）
- 一句话玩法：左右滑动接水果，60 秒内多接多得
- 核心操作：触摸滑动（移动端优先）
- 计分规则：接到+10，漏接-5，连击 5 个起 ×2
- 结束条件：60 秒时间到（MG-DESIGN-001 对应）
- 难度曲线：水果下落速度每 15 秒 +10%
- 失败反馈：结束面板显示分数+最高分+"再来一局"
- 裂变点：战绩海报分享（炫耀）+ 本地最高分榜（竞争）
- 美术风格：扁平矢量、品牌色 #FF5A5A
- 音效：WebAudio 合成（接/漏/结束三音），带静音开关
```

**铁律**：计分规则与结束条件不许写"待定"。写不出来就回第 4 节继续问，
绝不带着"待定"进代码阶段——审计的 MG-DESIGN-001/002 就是为这条设的。

### 混合模板

少数玩法横跨两类模板（如"答题+抽奖"：答对 5 题获得抽奖机会）。允许混合，
但必须指定**主模板**（决定核心循环与代码结构）与**副玩法**（只做一层挂载），
不许两个模板平起平坐——双核心等于无核心。

### 参数调优经验值

以下数值是大量 H5 小游戏的收敛经验，调参时先抄再改：

| 参数 | 经验值 | 为什么 |
|---|---|---|
| 单局时长 | 30~90 秒 | 超过 2 分钟，H5 场景跳出率陡增 |
| 学会成本 | 3 秒内上手 | 读不懂规则的用户不会给你第二次机会 |
| 首次正反馈 | 开局 10 秒内 | 第一次得分/过关越早，留存越高 |
| 难度首档 | 前 30 秒友好 | 先让玩家爽，再让他难 |
| 失败惩罚 | 轻（扣分/减速）而非重开 | 重惩罚劝退小白，轻惩罚驱动"再来一局" |
| 每局变量 | 至少 1 个随机要素 | 固定套路玩 3 局就腻，随机带来"再来"的理由 |

## 6. 反模式

- ❌ 玩法现编：不匹配模板、从零发明复杂规则 → 小白 3 天做不完，bug 无数
- ❌ 结束条件模糊："玩到不想玩为止" → 没有终点就没有分享冲动
- ❌ 计分玄学："玩得好就高分" → 玩家不知道自己为什么输，不会再来一局
- ❌ 真奖品无后端：纯前端抽奖发真奖品 → 必被刷爆，且涉嫌违反促销合规
- ❌ 操作复杂：又要点又要滑还要摇 → 移动端 3 秒学不会就流失
- ❌ 时长失控：单局 5 分钟起 → H5 场景下跳出率飙升

## 7. 自检与反馈

**质检门**（本 skill 输出必须通过）：
- [ ] 模板已匹配且已告知用户选择理由
- [ ] GDD 一页纸已输出，计分规则与结束条件无"待定"
- [ ] 澄清问题 ≤5 个
- [ ] 有真奖品时已声明"需要后端+防刷"

**标准冒烟用例**：输入"做个接水果游戏" → 应匹配模板 B，输出 GDD 含"60 秒时间到"结束条件与"+10/-5"计分规则。

**一键反馈**：发现模板覆盖不了的玩法，以 `[QC] <玩法描述>` 为标题提交到
https://github.com/lhg-plugs/lhg-mini-game/issues，正文写清"玩法一句话 → 期望匹配的模板 → 现有模板为什么不够"。
